# Decisions

Every default chosen while building Chore Heroes, and why. Newest decisions are at the bottom of each section.

## Tooling & environment

| #   | Decision                                                                                     | Why                                                                                                                                                                   |
| --- | -------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Expo SDK 57** (React Native 0.86, React 19.2, TypeScript 6, expo-router 57)                | Latest stable SDK on npm when the project was created (2026-10-11).                                                                                                   |
| 2   | **`expo-audio` instead of `expo-av`**                                                        | `expo-av` was removed from the Expo SDK and is not in SDK 57's native module list; `expo-audio` is its official successor.                                            |
| 3   | **Skills**: `frontend-design` and `ui-ux-pro-max` were **not available** in this environment | The design system (tokens, components, mascot) was hand-built in `src/theme` and `src/components`. The built-in `code-review` skill was used for a final review pass. |
| 4   | Expo docs website was unreachable from the build sandbox (network policy)                    | APIs were checked against the installed packages' TypeScript definitions instead.                                                                                     |
| 5   | `npx expo install` ran with `EXPO_OFFLINE=1`                                                 | The Expo API is unreachable here; offline mode uses the SDK's bundled version map, so versions are still SDK-matched.                                                 |
| 6   | `typedRoutes` **off**                                                                        | Typed routes are generated by the dev server; keeping them off makes `tsc` deterministic in CI.                                                                       |
| 7   | **Jest + `node:sqlite`** for repository tests                                                | Business rules are tested against a real SQLite engine (same SQL, triggers and constraints as the device) without native modules.                                     |
| 8   | React Native Testing Library **v14**                                                         | Current major; its APIs are async (`await render`, `await fireEvent`).                                                                                                |
| 9   | `expo-dev-client` added                                                                      | Needed for the EAS `development` profile. Expo Go (SDK 57) also works for quick tries.                                                                                |
| 10  | `expo-asset` added explicitly                                                                | `expo-doctor` flagged it as a required peer of `expo-audio`.                                                                                                          |

## Product rules

| #   | Decision                                                                                                                                                                                                                                 | Why                                                                                                                                                                                             |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 11  | **Weeks run Monday–Sunday** (ISO)                                                                                                                                                                                                        | Used for weekly tasks, weekly reward limits and the dashboard chart. Consistent and unambiguous.                                                                                                |
| 12  | **Stars are debited when a child asks for a reward**, and refunded (new ledger row) if the parent declines                                                                                                                               | Guarantees the balance can never go negative and the same stars can't be spent twice while requests are pending. Matches the spec's example ledger row (`-10` at redemption).                   |
| 13  | **Weekly reward limit is per child**, counts requested + approved redemptions; a declined request frees the slot                                                                                                                         | Fair for siblings; a "no" shouldn't use up the week's allowance.                                                                                                                                |
| 14  | **Reward approval defaults to ON; task approval defaults to OFF**                                                                                                                                                                        | Rewards involve the parent anyway (screen time, trips); most jobs should feel instant to a child.                                                                                               |
| 15  | **"Not yet" on a job** returns it to the child's list with an encouraging note, flagged "Try again"                                                                                                                                      | Gentle correction instead of a hard rejection; the job can still be completed that day.                                                                                                         |
| 16  | **Child "undo"** (same day only)                                                                                                                                                                                                         | Young children mis-tap. Auto-awarded stars are reversed with a compensating `task_undo` ledger row; parent-approved jobs can't be undone by the child; blocked if the stars were already spent. |
| 17  | **Streak = days with at least one job done** (approved or waiting). Today never breaks the streak until it's over.                                                                                                                       | Kind and achievable for 6–9 year olds; no "you lost your streak" shaming — a missed day shows "Welcome back… let's light the flame again!"                                                      |
| 18  | **One-time jobs stay on the list until done**; **weekly jobs are visible all week** until done                                                                                                                                           | Avoids "missed it forever" pressure; matches how families actually use these.                                                                                                                   |
| 19  | **Instances are materialized lazily** (Today screen) **plus a 14-day back-fill** (app start, dashboards)                                                                                                                                 | History and completion rates include days the app wasn't opened, without a background job.                                                                                                      |
| 20  | **Editing a job applies from today**: open (not done) current/future instances are regenerated; finished history keeps its original name/stars snapshot                                                                                  | Never rewrites history, while edits show up immediately.                                                                                                                                        |
| 21  | **10 badges**: First Job, Helper Hero (10), Super Helper (50), Warm Flame (3-day), Bright Flame (7-day), Blazing Hero (14-day), Star Catcher (50★), Star Champion (100★), Treat Time (first reward), Perfect Day (all jobs in a day, ≥2) | Mix of effort, consistency and fun; all reachable within weeks. Badges are permanent once earned.                                                                                               |
| 22  | "Lifetime stars" for badges = stars from jobs only (net of undo), not manual bonuses                                                                                                                                                     | Badges reflect the child's own effort.                                                                                                                                                          |
| 23  | **Jar fills toward the next reward** the child can't yet afford                                                                                                                                                                          | Gives a concrete visual goal for pre-readers.                                                                                                                                                   |
| 24  | **1–6 children, ages 6–9**, profiles are archived, never deleted                                                                                                                                                                         | Spec limits; archiving preserves the ledger and history. At least one active child must remain.                                                                                                 |
| 25  | **26 job templates, 14 reward templates**; setup offers a pre-checked starter pack                                                                                                                                                       | Lets a family be running in ~2 minutes.                                                                                                                                                         |
| 26  | Manual adjustments: required reason (≥3 chars), max ±500, cannot make balance negative                                                                                                                                                   | Spec + sanity limits.                                                                                                                                                                           |

## Time & data integrity

| #   | Decision                                                                                                               | Why                                                                                                                                                     |
| --- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 27  | Dates are stored as **local calendar keys (`YYYY-MM-DD`) captured at the moment of the event**; timestamps are ISO UTC | A key never shifts after a time-zone change or DST; arithmetic on keys is done in UTC so DST can't skip/duplicate days.                                 |
| 28  | **Midnight rollover**: a timer to the next local midnight + re-check on app resume (also covers time-zone changes)     | "Today" updates even if the app stays open overnight. A job tapped after midnight on yesterday's screen is refused (`expired`) and the board refreshes. |
| 29  | `UNIQUE(task_id, child_id, period_key)` + conditional `UPDATE … WHERE status='todo'` inside serialized transactions    | A job cannot be completed twice for the same day/week, even with double taps.                                                                           |
| 30  | **Append-only ledger enforced by SQLite triggers** (UPDATE/DELETE abort)                                               | Integrity is guaranteed by the database, not just by app code. Corrections are always new rows.                                                         |
| 31  | Migrations: numbered, each in a transaction, **additive only**, never edited after shipping                            | Schema changes can't lose data; a failing migration rolls back completely (tested).                                                                     |
| 32  | Full reset = drop all tables and re-run migrations                                                                     | The only operation allowed to remove ledger rows; explicit, double-confirmed parent action.                                                             |

## Security & privacy

| #   | Decision                                                                                                                                                   | Why                                                                                                                                                                                   |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 33  | PIN stored as **salted, 2,000-round SHA-256** (pure JS, no extra native module)                                                                            | Keeps the PIN out of plain text. A 4-digit PIN is a child gate, not strong crypto — documented as such.                                                                               |
| 34  | Weak PINs (1111, 1234, 9876…) are refused                                                                                                                  | Those are the first things kids try.                                                                                                                                                  |
| 35  | **Lockout** after 5 wrong PINs: 30 s, growing to 5 min; persisted in the DB                                                                                | Relaunching the app doesn't reset it.                                                                                                                                                 |
| 36  | **Parent session auto-locks** after 5 min of inactivity and whenever the app goes to the background                                                        | Hand-the-iPad-back scenario.                                                                                                                                                          |
| 37  | **Settings & data export also need a math gate** (two-digit × one-digit, e.g. 17 × 6) once per parent session                                              | Spec: PIN + parental gate. Hard for 6–9 year olds to guess, trivial for adults.                                                                                                       |
| 38  | **Forgot PIN** = answer 3 math gates in a row, then set a new PIN (data kept)                                                                              | No accounts/e-mail exist to recover with; erasing all data would be too harsh.                                                                                                        |
| 39  | **Android release builds block the INTERNET permission** (`app.config.js`, preview + production profiles)                                                  | The shipped app physically cannot reach the network. Dev builds keep it for Metro.                                                                                                    |
| 40  | `android.allowBackup = false`; `AD_ID`, `RECORD_AUDIO`, storage and overlay permissions blocked                                                            | Children's data doesn't leave the device via cloud backup; no advertising ID.                                                                                                         |
| 41  | iOS **privacy manifest**: no tracking, no collected data types                                                                                             | Kids Category requirement.                                                                                                                                                            |
| 42  | Notifications are **local only**; no push token is ever requested                                                                                          | The `expo-notifications` config plugin still adds the iOS `aps-environment` entitlement and Android `POST_NOTIFICATIONS`/`RECEIVE_BOOT_COMPLETED`; these enable local reminders only. |
| 43  | Export **excludes PIN hash/salt**                                                                                                                          | Exported files may be shared; secrets stay on device.                                                                                                                                 |
| 44  | No external links anywhere in the child experience; the only "grown-ups" entry point is a lock button on the hero picker (not on the child's Today screen) | Kids Category rule + "one primary action per screen".                                                                                                                                 |

## Design & accessibility

| #   | Decision                                                                                                                                                                     | Why                                                                                                                   |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 45  | Hero theme: royal purple + sunny star yellow on cream paper; mascot **"Sparky"**, a star with a cape and mask (SVG, `src/components/Mascot.tsx`), also used for the app icon | Consistent, friendly, high contrast; text tokens meet WCAG AA (≥4.5:1).                                               |
| 46  | **Nunito** (rounded, OFL) for UI; **OpenDyslexic** as the optional dyslexia-friendly font                                                                                    | Both bundled — no network font loading.                                                                               |
| 47  | Icons: **MaterialCommunityIcons** (bundled font) in colored bubbles                                                                                                          | Thousands of clear glyphs offline; every icon name is verified by a unit test.                                        |
| 48  | **Sounds are generated by code** (`scripts/generate-sounds.js`)                                                                                                              | No licensing questions; tiny WAVs. Audio session is "ambient": respects the silent switch and mixes with other audio. |
| 49  | Haptics follow the **Sound** toggle                                                                                                                                          | "Quiet mode" should be fully quiet.                                                                                   |
| 50  | Text-to-speech: rate 0.9, US English; job cards have a dedicated 64pt speaker button; the board greeting is spoken once on open                                              | Pre-readers hear everything without reading; tapping the card itself always means "done".                             |
| 51  | Text scales with Dynamic Type up to a per-style cap (body 2.2×, headings 1.6–1.8×, big numbers 1.2–1.3×)                                                                     | Largest accessibility sizes stay usable without clipping card layouts.                                                |
| 52  | Reduce motion = app toggle **or** system setting, applied globally via Reanimated's `ReducedMotionConfig` plus per-component checks                                          | Celebrations become a simple modal; no flying stars, bobbing or springs.                                              |
| 53  | Two-pane layout when landscape and width ≥ 900pt; grids pick columns from available width                                                                                    | iPad landscape: tasks + star jar/streak side panel; parents get list + editor side by side.                           |
| 54  | Web export is used **only as a smoke test**; not a product target                                                                                                            | Confirms the app compiles and screens render; native behaviour must be verified on devices.                           |

## Changes from the code-review pass

The `code-review` skill reviewed the whole branch; every finding was fixed and covered by tests where testable.

| #   | Decision                                                                                                                                                                       | Why                                                                                                                                                                                                      |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 58  | **One SQLite connection; every write (standalone or transaction) goes through one JS mutex** using `BEGIN IMMEDIATE` (no `withExclusiveTransactionAsync`), plus `busy_timeout` | `withExclusiveTransactionAsync` opens a second connection, so a concurrent standalone write could fail with SQLITE_BUSY or land inside another transaction. The Jest adapter mirrors the same semantics. |
| 59  | **PIN recovery uses a harder gate** (two-digit × two-digit, three in a row) and is hidden while the PIN pad is locked out                                                      | The standard gate (e.g. 12 × 3) was within reach of a 9-year-old, which would have bypassed the PIN lockout.                                                                                             |
| 60  | **A changed schedule starts from today**, and a job is never re-offered in a period where it was already finished under a previous schedule                                    | Switching a finished daily job to weekly (or one-time) on the same day would otherwise allow earning its stars twice.                                                                                    |
| 61  | **Badge evaluation runs in one transaction and reports only rows it inserted**                                                                                                 | Two simultaneous approvals could both announce the same badge.                                                                                                                                           |
| 62  | **"Perfect Day" counts only approved/done jobs** (not ones still waiting)                                                                                                      | A later "not yet" from the parent would otherwise leave a permanent badge for a day that wasn't perfect. Archiving an unfinished job does remove it from that day (the parent decided it wasn't needed). |
| 63  | Parent area re-checks the 5-minute session on every render (and every 5 s), not only on a 15 s timer                                                                           | Closes a window where an expired session still showed parent screens.                                                                                                                                    |
| 64  | Child undo distinguishes "from another day" and "a grown-up already checked it"                                                                                                | Accurate, kind feedback.                                                                                                                                                                                 |
| 65  | Today/shop/dashboard queries scoped to the current period and grouped (no N+1, no write lock on a normal refresh)                                                              | Performance stays flat as history grows.                                                                                                                                                                 |
| 66  | SVG clip ids are unique per star jar instance, and spring overshoot is clamped                                                                                                 | Found by the web smoke test: two jars on the navigation stack shared one id, and the fill went negative when emptying.                                                                                   |
